The ClearPlay app (video_profanity_censor package) crashes with an out-of-memory kill when processing long, multichannel feature films (e.g. 2 hours, 5.1 channels, 48kHz) with a MEDIUM Whisper model on a 16GB machine. RAM climbs to ~10–12GB during transcription and stays there, then swap spikes to its max within seconds during the audio censoring stage and the OS kills the process. Explore the source to understand the pipeline in censor_engine.py, the transcription in speech_recognizer.py, and the censoring in audio_processor.py. There are two independent, stacking root causes, and I want you to fix only these two — keep the changes minimal and don't touch audio_extractor.py.

Root cause 1: the faster-whisper (CTranslate2) model loaded by SpeechRecognizer is never released. It holds several GB of RAM but is only needed during transcription — profanity detection and censoring operate on the transcription result, not the model. Add a method to release the model (drop the model reference, force a gc.collect(), make it idempotent) and call it in CensorEngine immediately after transcription finishes and before censoring starts, in a finally block so it runs even if a later stage fails.

Root cause 2: AudioProcessor.censor() decodes the entire audio track into an in-memory buffer via pydub (AudioSegment.from_file), which is ~4GB for such a film plus a second copy for the output — stacked on the un-freed model, this exceeds RAM. Rewrite censor() to stream through a single FFmpeg filtergraph instead (probe for duration/rate/channels rather than decoding; use a volume filter with an enable expression to silence windows for MUTE, and a gated sine generator mixed over muted windows for TONE) so peak memory is bounded and independent of track length. Preserve all existing behavior exactly: the public signature and CensorResult, the zero-detection passthrough, the per-detection window math (buffer, max_word_duration_ms cap trimmed from the start, boundary clamping, skipping non-positive windows), overlap handling, the 10ms boundary crossfade, total_censored_duration and segments_censored accounting, the progress-callback semantics, and the _build_export_params encoding parameters. Finally, run the test suite; if preservation tests assert byte-for-byte equivalence with the old pydub output, update them to assert behavioral equivalence (output duration matches, MUTE regions near-silent, TONE regions at the tone frequency, non-censored regions unchanged, accounting identical) and document why.
